# Данные и разрешения: фактическая основа декларации

Срез текущей реализации для Weigh Together 1.0, 2026-10-06. Это техническая основа декларации магазина. [Политика](privacy-policy.html) воспроизводимо создаётся из `app/src/main/res/raw/privacy_policy_ru.txt`, который поставляется в приложении. Имя разработчика Александр Палицин и контакт i@palixander.ru подтверждены владельцем. Публичное размещение HTML и внесение URL в консоль учитываются отдельно; ссылка на файл приватного репозитория не заменяет публичный URL.

## Что обрабатывается

| Данные | Для чего и где |
| --- | --- |
| Имя, пол, рост, дата рождения человека, выбранная фотография | Локальный профиль; параметры для расчёта состава тела, фото для отображения |
| Вес, импеданс, дата/время, расчётные показатели, происхождение записи, статусы синхронизации | Локальная Room БД; история, графики и назначение измерений |
| Имя, вид, пол, порода, дата рождения, рост/категория взрослого веса и фотография питомца, его вес | Локальный профиль, история, графики и справочные ориентиры |
| Имя и Bluetooth-адрес выбранных весов | Локальная привязка к устройству; не координаты пользователя |
| Настройки, расписания, выбранный звук напоминания | Локальное хранение; уведомления/будильники |

Основные источники: `app/src/main/kotlin/com/palixander/weightogether/data/`, `profile/ProfilePhotoStore.kt`, `backup/BackupContract.kt` (пути Kotlin относительно `app/src/main/kotlin/com/palixander/weightogether/`). Автоматический Android backup отключён в manifest; `res/xml/data_extraction_rules.xml` исключает данные также из облачного backup и переноса устройства.

## Передача и контроль пользователя

- В исходном manifest нет `INTERNET`; собственный сервер, рекламный или аналитический SDK не подключены в текущей конфигурации приложения. Основные функции работают локально без сетевого аккаунта. Перед отправкой повторно сверить **merged manifest и зависимости финального release APK**, а не только исходный manifest.
- После предоставления разрешений интеграция записывает поддерживаемые показатели основного профиля в **Health Connect** на устройстве: вес, процент жира, массу воды, костную массу, безжировую массу и базальный обмен. Код `sync/HealthConnectGateway.kt` использует `insertRecords`; разрешений чтения медицинских данных в исходном manifest нет. Доступ сторонних приложений к Health Connect управляется отдельно пользователем через Android/Health Connect.
- Отзыв разрешений/отключение интеграции прекращает последующую запись. Удаление данных в Weigh Together **не удаляет ранее записанные данные из Health Connect**; ими нужно управлять в Health Connect.
- Пользователь может экспортировать JSON резервной копии через системный выбор файла. Текущий формат `scalesync-backup` — **v9**, включая рост питомца; импорт поддерживает v1–v9. Файл содержит профили, измерения, настройки, выбранные весы и напоминания, но не фотографии профилей. Приложение не шифрует JSON. Если пользователь выбирает облачного поставщика документов, файл передаётся ему по выбору пользователя; поэтому нельзя обещать, что данные «никогда не покидают телефон».
- Фотография выбирается системным Photo Picker или создаётся внешним приложением камеры через временный URI FileProvider, затем обрабатывается и сохраняется в приватном хранилище. Приложение не запрашивает полный доступ к медиатеке или разрешение `CAMERA` в исходном manifest.
- Локальные записи/профили можно удалять через интерфейс; очистка данных приложения или его удаление удаляет его приватное хранилище. Экспортированные файлы и ранее переданные записи Health Connect остаются отдельно и удаляются пользователем отдельно. Не заявлять удаление этих копий вместе с приложением.
- Ссылки на справочные источники могут открываться во внешнем браузере; политика внешнего сайта применяется отдельно.

В анкете RuStore описывать чувствительные данные о здоровье и физические параметры даже при локальной обработке. Конкретные ответы о сборе/передаче зависят от определений полей консоли; не подменять их общим заявлением «данные не собираются».

## Обоснование разрешений исходного manifest

| Разрешение Android | Сценарий и ограничение |
| --- | --- |
| `BLUETOOTH`, `BLUETOOTH_ADMIN` (до API 30) | Обнаружение и работа с BLE-весами на старых Android |
| `ACCESS_FINE_LOCATION` (до API 30) | Системное требование для BLE-сканирования; координаты пользователя не определяются приложением |
| `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT` | Поиск выбранных весов и работа с Bluetooth на Android 12+; scan имеет `neverForLocation` |
| `POST_NOTIFICATIONS` | Уведомления об измерениях, отложенном назначении, фоновой работе и напоминаниях |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CONNECTED_DEVICE` | Сервис `ReliabilityScanService`: режим повышенной надёжности BLE с постоянным уведомлением |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | `WeighingAlarmSoundService`: воспроизведение звука выбранного пользователем напоминания-будильника |
| `USE_FULL_SCREEN_INTENT` | Полноэкранное открытие напоминания-будильника при разрешённом системном доступе |
| `SCHEDULE_EXACT_ALARM` | Точное время пользовательского напоминания-будильника; специальный доступ Android |
| `RECEIVE_BOOT_COMPLETED` | Восстановление фонового сканирования и расписаний после перезагрузки/обновления |
| `WAKE_LOCK` | Поддержка выполнения фоновых задач/напоминаний; сверить итоговое использование и добавления библиотек по merged manifest |
| `health.WRITE_WEIGHT` | Запись веса в Health Connect по разрешению пользователя |
| `health.WRITE_BODY_FAT` | Запись процента жира |
| `health.WRITE_BODY_WATER_MASS` | Запись массы воды |
| `health.WRITE_BONE_MASS` | Запись костной массы |
| `health.WRITE_LEAN_BODY_MASS` | Запись безжировой массы |
| `health.WRITE_BASAL_METABOLIC_RATE` | Запись базального обмена |

У последних шести разрешений полный префикс `android.permission.health.`; у остальных — `android.permission.`. Ручной ввод веса не требует BLE или Health Connect. Отказ от разрешений ограничивает соответствующие дополнительные функции, а не локальный дневник.

При заполнении [декларации RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/new-version-app/declare-app-permissions/how-to-declare-permissions) приложить требуемые консолью демонстрации сценариев. Особое внимание: медицинские данные, геолокация старых Android, точные будильники, полноэкранные уведомления и foreground services. Этот список не является подтверждением одобрения разрешений магазином.
