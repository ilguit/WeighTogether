# Дизайн-пакеты

Каталог хранит утверждённые UI/UX-артефакты GitHub-задач. Для каждой задачи используется отдельный каталог `docs/design/<issue-number>/`.

Рекомендуемая структура:

```text
docs/design/<issue-number>/
├── README.md       # Каноническое резюме утверждённого дизайна
├── prototype.html  # Интерактивный прототип, если создавался
├── preview.png     # Основное визуальное превью
└── *.png           # Дополнительные обязательные состояния при необходимости
```

`README.md` дизайн-пакета должен содержать:

- ссылку на issue и комментарий `Design specification`;
- дату утверждения;
- scope и non-scope;
- структуру экранов и переходов;
- матрицу состояний, ширин и flavors;
- accessibility-требования;
- сохраняемую бизнес-логику;
- список файлов пакета;
- способ локального открытия прототипа;
- ограничения прототипа: что он демонстрирует, но не реализует.

`prototype.html` обязателен только тогда, когда для задачи создавался интерактивный прототип. `preview.png` обязателен для любой визуальной дизайн-задачи. Дополнительные изображения добавляются только для состояний, которые нельзя ясно показать основным превью.

Дизайн-пакет публикуется в task-ветке на стадии `Design Ready` по регламенту из корневого `AGENTS.md`. Ссылка в issue должна быть commit permalink, чтобы она оставалась доступной после удаления ветки.
