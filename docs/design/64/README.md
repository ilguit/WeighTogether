# Design specification — definitive version 5

Эта самодостаточная версия полностью заменяет все предыдущие Design specification и correction-комментарии. Для реализации не требуется обращаться к заменённым спецификациям.

## A0. Нормативный словарь и version/history contract

- **Измерение** — сохранённый или предварительный результат одного события взвешивания с датой/временем, владельцем `accountId`, исходными значениями и зафиксированным контекстом, который хранится по контракту I.
- **Показатель** — один из 16 именованных видов данных раздела B, например «Жир» или «Основной обмен».
- **Значение показателя** — числовое значение конкретного показателя в конкретном измерении вместе с канонической единицей Q1; оно может отсутствовать.
- **Интерпретация** — вычисленный UI-результат применения одной шкалы к значению показателя в контексте интерпретации: категория, semantic color и полный список зон либо один из статусов недоступности.
- **Шкала интерпретации** — версионированный набор источника, области применимости, обязательных входов, упорядоченных категорий и half-open границ для одного показателя. Шкала не является диагнозом.
- **Справка о показателе** — локальный offline AlertDialog из H с объяснением, зависимостями, ограничениями, набором норм, источником и дисклеймерами; это не сама шкала и не медицинская рекомендация.
- **Справочный диапазон** — одна именованная зона шкалы с точными нижней/верхней границами и правилами включения. Это не персональная цель и не диагностический референс лаборатории.
- **Недоступная интерпретация** — типизированный результат без категории: «Норма не определена», «Нет нормы для вашего возраста или параметров», «Недостаточно данных профиля» или «Нет данных» по E/G0.
- **Контекст интерпретации** — значение и дата измерения, владелец `accountId`, сохранённый для измерения рост и его origin, а также текущие пол и дата рождения профиля владельца, из которой считается хронологический возраст на дату измерения. Изменение текущего пола/даты рождения может изменить интерпретацию истории; сохранённый рост прошлого измерения не заменяется текущим, кроме явно помеченной legacy restoration.
- **Набор норм** — согласованный пакет всех шкал под публичным именем «Справочные нормы ScaleSync, версия 1» и пользовательской строкой `Набор норм: ScaleSync 1`.

Версия 1 единообразно применяется при отображении как новых, так и всех исторических измерений; snapshot вычисленной категории в БД не является источником истины. Любое изменение границ, domain, источника или смысла категории — отдельное продуктовое решение и новый номер набора норм. В рамках #64 автоматическое обновление набора, параллельное отображение старой версии и индивидуальное закрепление версии за измерением не вводятся.

## A. Неподвижные продуктовые решения

- Публичное имя набора: **«Справочные нормы ScaleSync, версия 1»**.
- Категории являются потребительской интерпретацией, не диагнозом.
- Scope: Summary, раскрытая History, Preview RESULT; 16 человеческих показателей.
- Out of scope: Charts/reference bands, editor classification, pets, remote content, English, передача категорий в Health Connect.
- В свернутой Summary: число, единица, категория и цвет; без границ и info-actions.
- В раскрытой Summary/History и Preview: все зоны, границы и отдельная info-кнопка 48×48 dp.
- Справка: локальный AlertDialog; внешний браузер используется только для источника.
- Категория считается по raw Double. Единственное исключение — OMRON SMM, где источник требует округления процента до 0,1% перед классификацией.
- Half-open policy: нижняя граница включена, верхняя исключена.
- Все тексты русские и доступны офлайн.

## B. Уникальная раскладка 16 показателей

Всего ровно 16 полей, без дублирования.

1. Вес показывается один раз отдельным крупным блоком.
2. Остальные 15 при раскрытии показываются один раз:

**Основное**
- Импеданс
- BMI

**Состав тела**
- Жир
- Масса жира
- Вода
- Масса воды
- Белок
- Масса белка
- Безжировая масса

**Мышцы и кости**
- Мышечная масса
- Скелетная мышечная масса
- Костная масса

**Метаболизм**
- Висцеральный жир
- Основной обмен
- Возраст тела

В свернутой Summary прежние четыре key metrics остаются компактным обзором. При раскрытии компактный key-grid заменяется, а не дублируется полным grouped layout.

Preview RESULT расширяется до тех же 16 полей и групп. Полный одноразовый профиль остаётся обязательным; RESULT при missing profile недостижим. Частичный расчёт Preview не вводится.

## C. Общий presentation contract

### Полная ячейка

- название;
- нейтральная info-кнопка;
- значение и единица;
- текущая категория;
- вертикальный список всех зон;
- текущая зона: цветная точка и bold;
- остальные: нейтральная точка и обычный текст.

Две колонки только при width ≥360 dp и fontScale <1,3; иначе одна. Текст переносится, не обрезается.

### Свернутая Summary

У веса и четырёх key metrics:

- значение;
- единица;
- категория;
- tonal status color.

Границы и info-кнопки отсутствуют. По умолчанию карточка свернута; выбор не хранится между запусками.

### History

Новые элементы только в раскрытой записи. Множественное раскрытие сохраняется.

### Preview

- все 16 показателей;
- «Предварительно: <категория>»;
- help-dialog временно заменяет preview-dialog;
- закрытие help восстанавливает preview, scroll/draft/result и фокус вызвавшей кнопки.

## E. Dialog contract и финальные общие тексты

Порядок:

1. Значение и категория.
2. Все зоны.
3. Что означает.
4. Как рассчитано.
5. От чего зависит.
6. Ограничения.
7. Источник: сначала обязательная строка `Набор норм: ScaleSync 1`, затем название конкретной шкалы/документа и единственное доступное source-action.
8. Дисклеймер.

Кнопки:

- «Открыть источник нормы» — если rating source есть;
- «Открыть источник описания» — если rating source отсутствует;
- «Закрыть».

Ошибка Intent:

> Не удалось открыть источник.

Manual edit:

> Измерение изменено вручную; связанные показатели могли не пересчитаться.

Legacy context:

> Рост для старого измерения восстановлен из профиля аккаунта-владельца.

Использованные данные:

> Для оценки использованы рост <N> см, текущий пол профиля и возраст <N> лет на дату измерения.

BIA:

> Показатель рассчитан по биоимпедансу и данным профиля. Он предназначен для наблюдения за динамикой, не является диагнозом и может меняться из-за условий измерения.

Противопоказания:

> Не используйте биоимпеданс при беременности, кардиостимуляторе, диализе, имплантированном медицинском оборудовании или выраженных отёках. При сомнениях проконсультируйтесь с врачом.

Unavailable:

- шкалы нет: «Норма не определена»;
- вне domain: «Нет нормы для вашего возраста или параметров»;
- inputs missing: «Недостаточно данных профиля»;
- value null: «Нет данных».

## G. Per-metric domain и classifier rules

### G0. Единый нормативный алгоритм применимости

Каждая шкала проверяется независимо от остальных. Категория доступна только на пересечении трёх условий:

1. значение показателя присутствует и является валидным для данного измерения;
2. все обязательные именно для этой шкалы данные профиля/измерения присутствуют;
3. возраст, пол, рост, вес, impedance и иные параметры, которые использует эта шкала, входят в опубликованную область её источника и в поддерживаемую область ScaleSync.

Запрещены экстраполяция за пределы области, clamp к ближайшей границе, подстановка соседней возрастной/половой шкалы и отключение всех классификаторов из-за недоступности одного из них. При неполном профиле независимые доступные шкалы продолжают работать; только зависящие от отсутствующих данных получают «Недостаточно данных профиля». Валидное значение вне области получает «Нет нормы для вашего возраста или параметров»; отсутствующее/невалидное значение — «Нет данных». Это правило имеет приоритет перед попыткой выбрать строку любой таблицы M.

Acceptance-набор включает комбинированные случаи: отсутствует рост, но доступна независимая шкала; отсутствует impedance, но Weight/BMI доступны; одна шкала вне возрастного domain, соседняя применима; ровно граничный возраст/рост/вес; запрет clamp и запрет выбора ближайшей таблицы.

Используется фактический хронологический возраст на дату измерения, не coerced age 10..100 из calculator.

ScaleSync-supported human composition starts at 10 years. Возраст 6–9 находится вне поддерживаемого profile/calculation domain #64 и всегда получает unavailable.

### Weight / BMI

- rating: SR1;
- age: 20–99 by product decision;
- height: 100–220 cm (intersection ScaleSync and legacy device);
- weight: 10–150 kg;
- impedance not required;
- thresholds BMI: 18,5 / 25 / 28 / 32;
- weight thresholds = BMI threshold × savedHeightMeters².

### Fat %

- SR1;
- full valid impedance measurement;
- age 10–99;
- height 100–220;
- weight 10–150;
- binary current sex;
- age bins: 10–11, 12–13, 14–15, 16–17, 18–39, 40–59, 60–99.

### Water %, muscle mass, bone mass, protein %, visceral fat, BMR

- SR1;
- full valid impedance;
- age 10–99;
- height 100–220;
- weight 10–150;
- required table inputs;
- BMR age 100 unavailable.

### Fat mass / FMI

- SR2;
- age 18–98;
- bins: 18–34, 35–54, 55–75, 76–98;
- age 75 deliberately remains in preceding group; 76 begins >75 group;
- binary current sex;
- saved height required;
- FMI = fatMassKg / heightMeters²;
- boundaries P5/P95.

Boundary tests: 34/35, 54/55, 74/75/76, 98/99.

### Skeletal muscle / OMRON

- SR3;
- age 18–80 inclusive;
- binary current sex;
- valid full measurement;
- SMM% = SMMkg / weightKg ×100;
- **exception:** decimal rounding to one digit uses BigDecimal.valueOf(percent).setScale(1, RoundingMode.HALF_UP); binary arithmetic or String-format rounding is not allowed;
- thresholds apply to this HALF_UP rounded decimal value.

Examples:

- raw 30,34% → rounded 30,3%; remains previous OMRON zone;
- raw 30,35% → decimal HALF_UP 30,4%;
- raw 30,39% → 30,4%; next zone.

Janssen offers no under-18 rating; SMM under 18 is unavailable.

### Metabolic age

- SR4 comparison pattern;
- age 18–99;
- compare stored integer to current chronological age on measurement date;
- lower / equal / higher;
- no ±3/5/10 tolerance.

### No-rating metrics

Impedance, water mass, protein mass, lean body mass:

- value can display in any valid measurement state;
- category always «Норма не определена»;
- source action opens SR5/SR6/SR7/SR9 respectively.

## H. Final copy package: 16 dialogs

### 1. Вес

**Что означает**

> Масса тела, непосредственно измеренная весами.

**Как рассчитана норма**

> Границы веса рассчитаны из сохранённого роста по порогам BMI Xiaomi Legacy. Поэтому категория веса всегда совпадает с категорией BMI.

**Зависит от**

> Сохранённого роста и веса. Импеданс не используется.

**Ограничения**

> Сам вес не определяет состояние здоровья. Категория не показывается младше 20 лет и вне области шкалы.

**Источник нормы**

> SR1. Кнопка «Открыть источник нормы».

### 2. Импеданс

**Что означает**

> Электрическое сопротивление между электродами весов. Оно используется как вход расчётов состава тела.

**Как рассчитано**

> Значение считывается из BLE-пакета весов в омах и отдельно не пересчитывается.

**Зависит от**

> Контакта стоп, схемы электродов, частоты, геометрии тела, гидратации, температуры кожи и условий измерения.

**Ограничения**

> Само значение не является показателем здоровья. Шкалы разных BIA-устройств невзаимозаменяемы; универсальной нормы нет.

**Источник описания**

> SR5. Кнопка «Открыть источник описания».

### 3. BMI

**Что означает**

> Соотношение веса и роста. BMI не показывает состав тела и не является диагнозом.

**Как рассчитано**

> Вес в килограммах делится на квадрат сохранённого роста в метрах. Категории используют Xiaomi Legacy пороги 18,5 / 25 / 28 / 32.

**Зависит от**

> Веса и сохранённого роста.

**Ограничения**

> Это не современные клинические классы WHO. До 20 лет категория не показывается.

**Источник нормы**

> SR1.

### 4. Жир, %

**Что означает**

> Расчётная доля жировой ткани в общей массе тела.

**Как рассчитано**

> Xiaomi-совместимая BIA-формула использует вес, импеданс, рост, возраст и пол. Категория использует возрастно-половую Xiaomi Legacy таблицу.

**Зависит от**

> Текущего пола профиля, возраста на дату измерения, сохранённого роста и условий BIA.

**Ограничения**

> Это оценка алгоритма, не прямое измерение жировой ткани. Полезнее сравнивать устойчивую динамику в похожих условиях.

**Источник нормы**

> SR1.

### 5. Масса жира

**Что означает**

> Расчётная масса жировой ткани в килограммах.

**Как рассчитано**

> Масса = вес × жир %. Для нормы вычисляется FMI: масса жира / рост²; результат сравнивается с P5/P95 Schutz.

**Зависит от**

> Расчётного жира, веса, сохранённого роста, текущего пола и возраста.

**Ограничения**

> P5–P95 являются популяционными процентилями взрослых Женевы, а слово «Норма» — продуктовая интерпретация ScaleSync. До 18 и после 98 лет шкала недоступна.

**Источник нормы**

> SR2.

### 6. Вода, %

**Что означает**

> Расчётная доля всей воды в организме. Это не количество выпитой воды.

**Как рассчитано**

> Xiaomi-совместимая формула выводит показатель из оценки состава тела; категория использует половую Xiaomi Legacy шкалу.

**Зависит от**

> Текущего пола, состава тела, гидратации и условий измерения.

**Ограничения**

> Не заменяет оценку обезвоживания или отёков.

**Источник нормы**

> SR1.

### 7. Масса воды

**Что означает**

> Расчётная общая масса воды в организме в килограммах.

**Как рассчитано**

> Вес × вода %.

**Зависит от**

> Размера тела и расчётной доли воды.

**Ограничения**

> Абсолютное количество закономерно выше у более крупного человека и само по себе не показывает гидратацию. Совместимой универсальной шкалы килограммов нет.

**Источник описания**

> SR6.

### 8. Мышечная масса

**Что означает**

> Расчётная масса мышечных тканей.

**Как рассчитано**

> ScaleSync вычитает из веса расчётную массу жира и костную массу. Категория использует Xiaomi Legacy пороги по полу и росту.

**Зависит от**

> Текущего пола, сохранённого роста, веса и всех BIA-входов.

**Ограничения**

> Значение зависит от алгоритма и не измеряет силу или функцию мышц.

**Источник нормы**

> SR1.

### 9. Скелетная мышечная масса

**Что означает**

> Расчётная масса мышц, обеспечивающих движения тела.

**Как рассчитано**

> Используется уравнение Janssen по росту, impedance, полу и возрасту. Для категории масса делится на вес, переводится в процент, округляется до 0,1% и сравнивается с таблицей OMRON.

**Зависит от**

> Текущего пола и возраста, сохранённого роста, веса и impedance.

**Ограничения**

> Janssen использовал whole-body BIA, Xiaomi — foot-to-foot. Перенос OMRON является потребительской интерпретацией. Не оценивает силу и не диагностирует саркопению. До 18 и после 80 лет норма недоступна.

**Источник нормы**

> SR3.

### 10. Костная масса

**Что означает**

> Расчётная минеральная составляющая костей.

**Как рассчитано**

> Xiaomi-совместимая формула использует пол и BIA-оценку безжирового компонента. Категория зависит от пола и веса.

**Зависит от**

> Текущего пола, веса и BIA-расчёта.

**Ограничения**

> Это не плотность костной ткани, не BMD/T-score и не обследование на остеопороз.

**Источник нормы**

> SR1. SR8 показывается только как неинтерактивная вторичная цитата о различии с BMD. Единственное действие диалога ведёт на SR1 согласно таблице N.

### 11. Белок, %

**Что означает**

> Расчётная доля белковых компонентов тела.

**Как рассчитано**

> Внутренняя Xiaomi-совместимая формула использует мышечную массу, вес и воду. Пороги Xiaomi Legacy: 16% и 20%.

**Зависит от**

> Всех входов мышечной массы и воды.

**Ограничения**

> Не показывает потребление белка, белок крови или качество питания.

**Источник нормы**

> SR1.

### 12. Масса белка

**Что означает**

> Расчётная масса белковых компонентов по внутренней формуле ScaleSync.

**Как рассчитано**

> Вес × белок %.

**Зависит от**

> Расчётных мышц, воды, белка и веса.

**Ограничения**

> Не является валидированной общей массой белка тела, лабораторным белком крови или нормой питания. Совместимой шкалы килограммов нет.

**Источник описания**

> SR7.

### 13. Висцеральный жир

**Что означает**

> Расчётный индекс жира вокруг внутренних органов.

**Как рассчитано**

> Xiaomi-совместимая регрессия использует пол, возраст, рост и вес. Xiaomi Legacy пороги: 10 и 15.

**Зависит от**

> Текущего пола и возраста, сохранённого роста и веса.

**Ограничения**

> Это безразмерная шкала алгоритма, не масса, процент, окружность талии или CT/MRI-площадь.

**Источник нормы**

> SR1.

### 14. Основной обмен

**Что означает**

> Примерная энергия, которую организм расходует за сутки в состоянии покоя.

**Как рассчитано**

> ScaleSync использует формулу по полу, возрасту, росту и весу. Порог нормы Xiaomi Legacy равен весу, умноженному на возрастно-половой коэффициент.

**Зависит от**

> Текущего пола и возраста, сохранённого роста и веса.

**Ограничения**

> Это не суточная цель калорийности, не рекомендация питания и не прямое измерение калориметрией.

**Источник нормы**

> SR1.

### 15. Возраст тела

**Что означает**

> Условный показатель алгоритма на основе состава тела.

**Как рассчитано**

> Xiaomi-совместимая регрессия использует рост, вес, возраст, impedance и пол. Категория сравнивает результат с текущим возрастом профиля на дату измерения по TANITA-паттерну.

**Зависит от**

> Текущего пола и даты рождения, сохранённого роста, веса и impedance.

**Ограничения**

> Не определяет биологический возраст и не используется для диагностики. Норма доступна только 18–99.

**Источник нормы**

> SR4.

### 16. Безжировая масса

**Что означает**

> Внутреннее расчётное значение Xiaomi Legacy, используемое формулой состава тела.

**Как рассчитано**

> Регрессия использует рост, вес, impedance и возраст, затем ограничивается техническим пределом алгоритма.

**Зависит от**

> Текущего возраста, сохранённого роста, веса и impedance.

**Ограничения**

> Поле не совпадает строго с клинической fat-free mass. Внешние FFMI-пороги к нему не применяются; технический clamp не является нормой.

**Источник описания**

> SR9.

## I. Migration, backup и профиль

Новые nullable поля концептуального контракта:

- ratingHeightCm;
- ratingHeightOrigin = CAPTURED | RESTORED_CURRENT_ACCOUNT;
- classifier category не сохраняется.

### DB migration

Для каждого measurement:

1. Найти account-владельца по measurement.accountId.
2. Взять heightCm именно этого account, не активного UI-профиля.
3. Если height отсутствует, сохранить null.
4. Пометить origin RESTORED_CURRENT_ACCOUNT.
5. Категории с обязательным ростом получают «Недостаточно данных профиля» при null.

### Новые измерения

- фиксируется nullable current height account-владельца в момент финализации;
- origin CAPTURED;
- weight-only также фиксирует height;
- unsaved Preview не сохраняется.

### Изменение профиля

- «Сохранить и пересчитать» обновляет значения и ratingHeightCm;
- «Сохранить без пересчёта» сохраняет прежний ratingHeightCm;
- manual edit сохраняет прежний ratingHeightCm;
- пол и дата рождения всегда текущие и могут менять историческую категорию.

Текст:

> Рассчитанные значения останутся прежними. Нормы истории продолжат использовать рост, сохранённый при измерении, но будут учитывать текущие пол и дату рождения.

### Backup

Новая версия schema включает nullable ratingHeightCm и origin.

Импорт старого backup:

1. Для каждого measurement использовать imported account с совпадающим accountId.
2. Восстановить его height или null.
3. Пометить RESTORED_CURRENT_ACCOUNT.
4. Не использовать active account приложения.
5. Старые backup остаются поддержанными.

Acceptance:

- два аккаунта с разным ростом получают собственный restored height;
- incomplete recovery account с null height импортируется и показывает «Недостаточно данных профиля»;
- round-trip новой schema сохраняет height/origin;
- manual edit и save-without-recalc не меняют height;
- recalc меняет.

## J. Error и focus contracts

Repository load error:

- новый state не добавляется;
- вне scope #64;
- существующие loading/empty остаются.

Preview calculation failure:

> Не удалось рассчитать показатели. Проверьте данные и повторите.

Поведение:

- isCalculating=false;
- step=PROFILE_EDITOR;
- draft сохранён;
- pending не удалён;
- retry доступен;
- постоянный inline error-block показывается после полей профиля и непосредственно над кнопкой «Рассчитать»;
- full profile validation остаётся обязательной;
- focus перемещается на inline error heading; кнопка сохраняет label «Рассчитать» и остаётся retry-action;
- изменение любого поля профиля очищает старую calculation error; повторный failure показывает её снова.

Focus:

- закрытие help из Summary/History возвращает фокус на вызвавшую info-кнопку;
- из Preview: сначала восстанавливается preview-dialog, затем фокус возвращается на исходную info-кнопку;
- source browser return сохраняет открытый help-dialog и scroll, если Activity не была уничтожена.

## O. Полная state matrix

### O1. Summary

| State | Contract |
|---|---|
| Loading, summary отсутствует | Прежний loading; интерпретация и help отсутствуют |

| Empty | Прежний empty; help отсутствует |
| Normal full, collapsed | Вес + 4 key metrics: value/unit/category/color; без границ/info |
| Normal full, expanded | 16 уникальных полей, все зоны и info-actions |
| Weight-only | Вес получает BMI-derived category при достаточном height и age 20+; composition values остаются null/«Нет данных» |
| Processing | Согласно Q8 интерпретация, границы и info-actions скрыты до финализации |

### O5. Accessibility parameterized contract

Визуально отображаемое formatted value является единственным значением, которое произносит TalkBack. Категория по-прежнему считается по raw Double, кроме OMRON HALF_UP exception.

Normal template:

> <Название>, <визуально отображаемое значение и единица>. <Категория>. Зоны: <полный список названий и границ>.

Preview template:

> <Название>, <визуально отображаемое значение и единица>. Предварительно: <категория>. Зоны: <тот же полный список названий и границ>.

Unavailable templates используют тексты из E и не произносят фиктивные зоны. После объединённого information node следует отдельная button node.

## P. Дополнительные acceptance criteria второго review

1. Definitive comment содержит все таблицы M1–M12 и реализуется без старых комментариев.
2. Для каждого field используется ровно один action из N.
3. OMRON использует BigDecimal.valueOf + HALF_UP, а не binary/String formatting.
4. TalkBack читает visual formatted value и полный zone list.
5. Preview failure имеет только inline contract; snackbar для calculation failure не используется.
6. State matrix O является нормативной, включая скрытие norms в Processing.
7. Вторичные source URLs не создают дополнительные actions.


## Q. Самодостаточные общие контракты и полная приёмка

### Q1. Матрица названий и единиц

Одинаковые названия и единицы используются в Summary, раскрытой History, Preview и help-dialog; accessibility произносит их развёрнуто.

|---|---|---|
| Вес | кг | килограмм(а/ов) |
| Импеданс | Ом | ом(а/ов) |
| BMI | кг/м² | килограмм на квадратный метр |
| Жир | % | процент(а/ов) |
| Масса жира | кг | килограмм(а/ов) |
| Вода | % | процент(а/ов) |
| Масса воды | кг | килограмм(а/ов) |
| Мышечная масса | кг | килограмм(а/ов) |
| Скелетная мышечная масса | кг | килограмм(а/ов) |
| Костная масса | кг | килограмм(а/ов) |
| Белок | % | процент(а/ов) |
| Масса белка | кг | килограмм(а/ов) |
| Висцеральный жир | уровень | уровень |
| Основной обмен | ккал/сут | килокалорий в сутки |

Скелетная мышечная масса визуально остаётся в килограммах; процент, округлённый HALF_UP до 0,1%, является только входом OMRON-классификатора и объясняется в help.

### Q2. Flavors и сохранение UI-state

- Единая сборка использует согласованные локальные тексты, классификаторы, зоны, цвета, help, Preview и accessibility.
- Flavor не меняет нормативы и не создаёт отдельный источник. Внешняя синхронизация Health Connect не получает категории, границы или справочные тексты.
- Раскрытие Summary сохраняется при configuration change/process recreation тем же механизмом saved UI-state, что и другие восстанавливаемые состояния экрана.
- В History одновременно раскрытые карточки сохраняют согласованное поведение списка; открытие новой карточки не сворачивает уже раскрытую.
- Help после configuration change либо безопасно восстанавливается с тем же metric/measurement, либо закрывается с восстановлением вызывающего экрана; потеря/подмена контекста недопустима.

### Q3. Visual и responsive acceptance

1. В свёрнутой Summary видны value/unit/category и status-color, но нет границ, списка зон и info-action.
2. В раскрытой Summary, раскрытой History и Preview видны все применимые зоны/границы и отдельная info-кнопка минимум 48×48 dp.
3. Status container использует точные токены D; само число сохраняет обычный content color. Цвет никогда не является единственным носителем категории.
4. При ширине 320 dp и минимальной поддерживаемой ширине нет горизонтального обрезания; карточки переходят в одну колонку.
5. При системном font scale 200%, длинных русских названиях, границах и unavailable-текстах нет наложения/обрезания; контент скроллируется вертикально.
6. AlertDialog прокручивает содержимое, а actions остаются достижимы. Строка `Набор норм: ScaleSync 1` идёт перед названием конкретного источника.
7. Все состояния проверяются в обеих flavors; palette проходит AA contrast check для текста соответствующего размера.
8. Декоративные маркеры зон не получают focus; выбранная зона выделяется цветом и начертанием, остальные остаются нейтральными.

### Q4. Functional acceptance

1. Summary содержит ровно 16 уникальных показателей: Weight один раз и остальные 15 без дублей; Preview RESULT также содержит все 16.
2. Collapsed/expanded, weight-only, processing, manual, legacy restored-height, multiple-expanded History и no-rating/out-of-domain/missing-input/missing-value соответствуют O.
3. Категории пересчитываются из current sex/birthDate и сохранённого measurement height; legacy height восстанавливается строго по `accountId`. Null height не получает default.
4. Все таблицы M тестируются на каждой границе: непосредственно ниже, ровно на границе, непосредственно выше; half-open policy едина. OMRON отдельно тестируется до и после HALF_UP.
5. G0 тестируется независимо для каждой шкалы и на частично заполненном профиле.
6. Каждая из 16 info-кнопок открывает правильный локальный диалог. В диалоге ровно один интерактивный source-action из N; secondary citations — только текст.
7. Ошибка открытия внешнего Intent показывает `Не удалось открыть источник.`, не теряет диалог/scroll/context.
8. Preview validation и calculation failure следуют J: inline error, focus, сохранённый draft, очистка ошибки при изменении поля и retry.
9. Processing скрывает категории/границы/info до финализации; preliminary Preview явно произносит и показывает `Предварительно`.
10. Room migration, backup export/import и старые backup проверяются для нескольких аккаунтов, null height и origin `CAPTURED`/`RESTORED_CURRENT_ACCOUNT`.
11. Экспорт/синхронизация наружу, Charts, editor classification и pets остаются без новых категорий.
12. Все русские строки находятся в локальных resources и доступны офлайн.

### Q5. Accessibility acceptance

- У каждого информационного блока одна merged node с видимым форматированным числом, единицей, категорией и полным списком зон; затем отдельная button node `Подробнее о показателе: <название>`.
- Порядок focus соответствует визуальному; headings секций диалога объявлены; source label читается до action.
- TalkBack произносит видимое округлённое значение, включая корректные русские формы единиц; raw Double не озвучивается.
- Unavailable не озвучивает фиктивные зоны. Категория и текущая зона доступны без распознавания цвета.
- После закрытия help/возврата из браузера/Preview focus восстанавливается по J; после calculation failure переходит на inline error heading.

### Q6. Явно неприменимые состояния

- Dark theme: в текущем продукте отсутствует и не вводится #64; при его появлении потребуется отдельная палитра и проверка.
- Server loading и remote help error: неприменимы, потому что справка и нормы локальны/offline.
- Dangerous/destructive actions и подтверждения: отсутствуют; #64 не изменяет и не удаляет данные.
- Pets: исключены из scope; человеческие нормы к ним не применяются.
- Chart reference bands и chart help: исключены из scope.
- Editor classification: исключена; ручное редактирование влияет только на последующее отображение измерения и warning.
- English/locales кроме русского: исключены из scope.
- Отдельный repository-error state: не добавляется; существующий экранный error/loading contract сохраняется.

## R. Закрытие замечаний третьего Design Review

1. L больше не импортирует требования из заменённых комментариев; Q содержит единицы, flavor/configuration contracts, полную приёмку и N/A.
2. Каждый из 16 диалогов показывает точный текст `Набор норм: ScaleSync 1` перед конкретным источником.
3. SR8 у костной массы — неинтерактивная secondary citation; единственный action ведёт на SR1.
4. G0 нормативно задаёт пересечение domain/inputs/value, независимость шкал и запрет extrapolation, neighbor substitution и clamp.
