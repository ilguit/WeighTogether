# Issue #130 — Напоминания о взвешивании

Утверждённый дизайн для [GitHub issue #130](https://github.com/ilguit/ScaleSync/issues/130).

## Scope

- У каждого сохранённого профиля человека и питомца собственный список еженедельных напоминаний.
- По умолчанию расписаний нет.
- Расписание содержит локальное время, один или несколько дней недели, тип `Обычное` или `Будильник` и признак активности.
- Доступны создание, редактирование, включение, выключение и удаление нескольких расписаний.
- Нажатие на уведомление открывает соответствующий пользовательский экран профиля/истории и не запускает измерение.
- Удаление профиля удаляет его расписания, snooze-состояние и системные события.

Не входят: одноразовые напоминания по дате, автоматический старт измерения, синхронизация расписаний между устройствами, полноэкранный звонок, непрерывная мелодия и выбор мелодии внутри приложения.

## Навигация

- Точка входа находится только в настройках сохранённого профиля:
  - человек: `Настройки → Профили → редактировать профиль → Напоминания о взвешивании`;
  - питомец: `Настройки → Профили → редактировать питомца → Напоминания о взвешивании`.
- На экране сводки/истории точки входа нет.
- Строка настроек показывает `Не настроены`, ближайшее активное время и число остальных, `Все выключены` либо `Требуется настройка`.
- Нажатие открывает список расписаний данного профиля. Строка расписания открывает редактор.
- В create-mode строка отсутствует до успешного сохранения профиля.
- В edit-mode с чистым draft переход прямой. При несохранённых изменениях guard предлагает: `Сохранить и продолжить`, `Отменить изменения`, `Продолжить редактирование`. Автосохранения нет; ошибка сохраняет draft и не открывает расписания.
- Для dialog-like pet editor список временно заменяет редактор полноэкранным вложенным состоянием; два слоя одновременно не показываются.
- Back: редактор расписания → список → настройки того же профиля → список профилей. Фокус восстанавливается на строке напоминаний.
- Deep link уведомления ведёт в профиль/историю, а не в настройки.

## Редактор расписания

- Поля: системный выбор времени, минимум один день недели, тип `Обычное`/`Будильник`.
- Новый draft: 09:00, текущий день недели, `Обычное`, включено. До сохранения расписания нет.
- Полный дубликат `(owner, time, normalized weekdays, importance)` не сохраняется.
- Удаление подтверждается.

## Уведомления

- `Обычное`: отдельный Android channel с `IMPORTANCE_DEFAULT` и звуком; уведомление можно смахнуть. Звук настраивается в Android.
- `Будильник`: точное событие и отдельный high-importance channel; ongoing-уведомление нельзя смахнуть, оно остаётся до нажатия.
- Полноэкранного UI и непрерывного звонка нет.
- Текст всегда содержит имя: `Пора взвеситься — {имя}`.
- Нажатие снимает уведомление, очищает активный snooze и открывает профиль без запуска измерения.
- Если профиль удалён между публикацией и нажатием, устаревший Intent открывает безопасный профиль по умолчанию/стартовый селектор и сообщает `Профиль больше недоступен`; измерение не запускается.
- У каждого расписания стабильные уникальные системные идентификаторы.
- Следующее регулярное совпадение планируется после срабатывания.
- `BOOT_COMPLETED`, `TIME_SET` и `TIMEZONE_CHANGED` выполняют reconcile.
- При DST сохраняется wall-clock время: gap сдвигается к первому валидному времени, overlap использует первое вхождение.

## Отложить

- Оба типа имеют действие `Отложить на 10 минут`.
- Snooze снимает текущее уведомление и создаёт одноразовый повтор через 10 минут, не меняя еженедельное расписание.
- На расписание допускается один snooze; повторное откладывание заменяет его.
- Для `Будильника` повтор остаётся точным и ongoing; для обычного сохраняется системная неточная семантика.
- Редактирование, выключение или удаление расписания, удаление профиля, replace-import и отзыв необходимых разрешений отменяют snooze.
- Если regular due instant ≤ snooze due instant, regular выигрывает и snooze очищается; иначе сначала публикуется snooze.
- Будущий snooze восстанавливается после reboot/time change по absolute instant; прошедший задним числом не публикуется.
- Snooze — локальное операционное состояние и не экспортируется.
- Каждый показ имеет persisted occurrence/generation token. Action принимается транзакционно один раз только для актуального token.
- Persisted snooze-state содержит generation, source occurrence, absolute due instant и status. Update/consume выполняется одной Room transaction или сериализованной repository operation до отмены либо публикации системного уведомления.
- Regular/snooze callbacks проходят сериализованную arbitration до публикации; проигравший становится no-op.

## Разрешения и системные ограничения

- При запрете `POST_NOTIFICATIONS` расписание сохраняется, но не публикуется; UI предлагает системные настройки.
- Если exact alarms недоступны, `Будильник` не деградирует молча до обычного, а показывает требуемое разрешение.
- Отключённый channel отображается у затронутого типа.
- Fallback настроек: конкретный channel/exact-alarm → общие уведомления приложения → карточка приложения → локализованная ручная инструкция.
- После возврата в приложение состояние перечитывается.
- Lock-screen visibility и DND зависят от Android/OEM и channel settings. Приложение не запрашивает обход DND и не обещает показ поверх lock screen.
- Отзыв разрешения может быть обнаружен при ближайшем `onResume`, reconcile, alarm callback или boot/time receiver. Callback повторно проверяет доступность перед публикацией.
- После повторной выдачи разрешения планируются только будущие regular occurrences; expired/consumed snooze не возрождается.

## Backup/import

- Backup содержит расписания с владельцем, временем, днями, типом и enabled-state; platform IDs и snooze не экспортируются.
- Новая версия schema; старый backup без расписаний означает: merge ничего не добавляет, replace создаёт пустой список.
- Merge сначала строит окончательные account/pet ID mappings, затем remap владельцев и только потом проверяет schedule ID и семантические дубликаты. Неоднозначность атомарно отклоняет import.
- Merge сохраняет активное локальное snooze-состояние для неизменённых локальных расписаний; импортируемый snooze отсутствует по контракту backup.
- Replace полностью заменяет локальные расписания snapshot из backup.
- Replace очищает все локальные snooze-состояния перед reconcile.
- Preview counts рассчитываются после remap и conflict checks.
- Профили и расписания записываются одной Room transaction.
- После commit идемпотентный reconcile отменяет отсутствующие platform events и планирует разрешённые включённые расписания.
- Ошибка post-commit reconcile сохраняет checkpoint `Требуется перепланирование` и автоматически повторяется; import завершён после успешного reconcile.

## Состояния, визуальные правила и accessibility

- Предусмотрены normal, empty, loading, unavailable и error states; при ошибке draft не теряется.
- UI выдерживает узкую ширину, длинные переводы и крупный системный шрифт; редактор прокручивается.
- Используются существующие Material 3/Huawei компоненты, цвета и интервалы.
- Тип обозначается текстом и иконкой, не только цветом.
- Touch targets не меньше 48×48 dp.
- Заголовки, переключатели, дни, статусы, ошибки и snooze-action имеют screen-reader semantics; snooze label включает имя и 10 минут.
- Строки добавляются во все поддерживаемые локали. Product flavors отсутствуют.

## Проверки приёмки

1. Human и pet profiles поддерживают несколько независимых расписаний, изначально пустых.
2. Точка входа есть только в настройках сохранённого профиля; dirty draft защищён guard, Back и focus корректны.
3. Обычное уведомление смахивается; `Будильник` остаётся до нажатия.
4. Нажатие открывает правильный профиль без старта измерения; удалённый профиль обрабатывается безопасно.
5. Snooze работает для обоих типов без изменения regular schedule и без двойных уведомлений.
6. Проверены duplicate action delivery, обе очередности regular/snooze callbacks и revoke→grant без stale resurrection.
7. Разрешения, channels, lock screen и DND обрабатываются без crash и без молчаливой деградации.
8. Reboot/time/timezone/DST сохраняют описанную семантику.
9. Backup merge/replace соблюдает remap, atomic validation и recoverable reconcile.
10. Проверены normal/empty/loading/unavailable/error, narrow width, large font, long localization и screen reader.
